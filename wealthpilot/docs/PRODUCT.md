# 产品设计与全链路规划

## 1. 要解决的问题

个人投资者常见的问题并非缺少一个“推荐买什么”的窗口，而是风险画像、持仓、目标和实际操作相互脱节。用户很难回答：当前资产结构是否适合期限？市场下跌时能否承受？目标需要每月投入多少？为什么要调仓？调完以后是否确实执行了计划？

知衡的核心对象是**一个可解释、可核对的个人模拟投资计划**。页面先展示可操作的资产工作台，避免把核心工具藏在介绍页后面。

## 2. 目标用户与场景

| 用户 | 场景 | 本版交付价值 |
|---|---|---|
| 有储蓄、缺乏配置框架的个人 | 整理资产并建立长期计划 | 填问卷、归类资产、比较配置和现金约束 |
| 已有投资组合的研究者 | 检查集中度、偏离和冲击 | 压力测试、费用预览、可追溯的模拟执行 |
| AI/金融科技开发者 | 快速搭建可演示的开源产品 | 无依赖启动、完整 API、模型适配器、测试和容器 |
| 理财教育者 | 演示期限与投入如何改变结果 | 全中文界面、可解释公式、固定假设标记 |

本版以人民币作为显示单位，但资产类别是抽象研究类别，不映射具体中国证券、基金或适当性规则。金额、期限和费用都由用户明确输入。

## 3. 主业务闭环

1. **认识约束**：期限、投资经验、收入、应急资金、负债和必要支出。
2. **形成画像**：风险意愿与财务承受能力取较低者，产生五档规则标签。
3. **整理资产**：录入权益、债券、黄金和现金金额，计算当前权重。
4. **生成配置**：选择风险模板，加入现金底线，显示目标权重及原因。
5. **检查后果**：当前和目标配置接受相同压力情景；目标规划计算资金缺口。
6. **解释决策**：规则助手或外部模型解释已经计算的结果，附基础来源。
7. **预览行动**：展示调仓前后金额、交易额、费率和预计费用。
8. **确认模拟**：服务端重新计算，事务入账，防止重复扣费和旧数据覆盖。
9. **复盘留痕**：保存问卷/资产变更和调仓记录，可导出当前研究快照。

补充路径：目标规划可独立运行，但始终以当前组合总额作为起点；修改目标不会偷偷改变资产配置或风险问卷。

## 4. 产品规则

- 不把“风险意愿高”直接等同于“承受能力高”。短期资金、应急不足和高息负债限制风险等级。
- 不将假设收益画成历史净值曲线。首页曲线是目标测算，标注固定年化假设和累计投入。
- 规则与大模型各司其职：金额、配置、费用由可测试代码计算；模型只解释，不能改写账本。
- 未配置模型时仍可操作全部核心流程，明确显示规则模式。
- 外部 AI 逐次征求同意，不默认发送完整财务档案。
- 人工确认是模拟入账的明确边界，预览不改变数据库。
- 组合由服务端保存；多窗口更新通过版本冲突处理，不能静默覆盖。

## 5. 信息架构

| 页面 | 主要输入 | 主要输出 | 下一步 |
|---|---|---|---|
| 资产概览 | 查看/编辑资产 | 总额、风险、偏离、目标缺口 | 更新问卷、进入配置 |
| 风险测评 | 七项财务与风险输入 | 分数、等级、限制原因 | 查看配置 |
| 智能配置 | 资产金额、费率 | 当前/目标、费用和交易明细 | 预览并确认模拟 |
| 策略研究 | 费用假设、方案选择 | 三方案风险/费用对照、方差贡献 | 保存模拟目标后预览调仓 |
| 压力测试 | 读取当前组合 | 四个冲击情景、目标对照、假设参数 | 重新审视风险 |
| 目标规划 | 金额、年限、月投入、收益和通胀 | 期末金额、购买力、所需月投入 | 修改目标或投入 |
| AI 理财助手 | 问题、外部处理同意 | 规则/模型解读和来源 | 理解测算，不直接下单 |
| 操作记录 | 读取或导出 | 变更详情、调仓费用 | 复盘 |

## 6. 验收指标

这些是产品验收目标，不是已经获得的业务统计：

- 新用户无需密钥或依赖安装即可完成演示闭环。
- 每个配置结果可追溯到输入、规则版本与触发原因。
- 预览无写操作；模拟执行保证资产扣费守恒。
- 相同幂等请求不会重复扣费；不同负载使用同一幂等键会被拒绝。
- 所有金融数值输入经服务端校验，NaN、无穷值、非法类型和越界值被拒绝。
- 演示数据、手动数据、规则解读、模型解读状态不混淆。
- 模型服务失败时核心理财工具仍可使用。

## 7. 落地路径

### 阶段 A：当前交付，个人研究与开源演示

使用本机 Node 或单实例容器部署，录入抽象资产金额，进行计划和模拟。可作为作品集、教学工具、投顾业务原型或后续系统的计算基础。

### 阶段 B：行情与研究能力

引入证券主数据（证券标识、交易所、币种、最小交易单位），由具有使用许可的行情源导入价格。必须保存来源、时间、时区、币种和质量标记；陈旧价格不得伪装为实时估值。再引入含分红/复权、退市和交易日处理的历史数据，加入样本外回测、费用与滑点、基准及模型版本。未完成这些步骤前，不声称策略历史表现或收益优势。

### 阶段 C：身份、数据与团队应用

引入独立用户和账户所有权，所有查询都按账户授权；启用成熟身份服务、MFA、加密与备份恢复演练。将限流和会话移到共享持久层，补充数据导出/删除流程及运维监控。

### 阶段 D：受控商业试点

由目标市场的专业人员审查业务定位、适当性、营销表述、费用、利益冲突和人工服务机制。真实订单必须使用独立的授权、风控、订单状态机和对账；不能把模拟执行接口直接连到券商。先在严格隔离的试点范围评估。

## 8. 商业化方向与验证方式

潜在方向包括个人研究订阅、机构内部研究席位、理财教育工具和 API 服务。这些仅是产品假设，没有市场需求或收入数据。先访谈用户，观察问卷完成率、计划建立率、复盘频次和解释满意度；不使用“收益提高”作为未经验证的营销承诺。若对外收费或提供个性化投资服务，先明确具体业务性质与适用要求。
